## Design laws

- **Take universe is DERIVED, never stored.** Pair placement takes = seeds for the placement first, then the placement's clip in each retained render version (`sortedRenderVersions` ascending, continuation-only versions included — their pair clips are reuses and dedupe away), deduped by `clipPath` (a REUSED clip travels verbatim across versions and is ONE take whose origin is the earliest version; `carriedByVersionIds` tells the reuse story). Take number = first-appearance order. Continuation/ending placements keep `ShotContinuationRecord` as their universe.
- **Selection is the only new persisted state:** `ProjectShot.segmentTakeSelections: [ShotSegmentTakeSelection]` (`placementKey`, `clipPath` = immutable file identity like razor pins, `versionId`, `requestId`, `selectedAt`); tolerant decode default `[]`; `normalized()` prunes dangling selections → silent fallback to today's law, never a refusal.
- **One selection law** at every "which clip represents this placement" resolver: continuation selected take → **pair selection** → playable version clip → seed.
- **Fingerprint overlay, not append:** `shotOutputFingerprint`'s clip basis substitutes the selected clip *for its placement*, so selecting the take that already plays is fingerprint-neutral (no spurious scope re-flatten, no false stale continuation); a real change invalidates scope caches and stales dependent continuations honestly. Scope projections (`ShotOutputScope.project(from:)` ShotOutputScopes.swift:24, `shotOutputPrefix` ShotSequenceModels.swift:66) copy the whole shot then filter entries, so selections carry over for free; the basis ignores selections whose entries are absent from the projection.
- **THE FRESH TAKE LAW:** on `upsertingRenderVersion(activate: true)` of a **ready** version, drop selections for placements whose clip file appears in no earlier version and no seed; reused clips leave selections alone; a `generating` version never clears (playback substitutes the last ready version mid-render). This mirrors today's behavior (a new active version already changes what plays) and is not undoable — re-picking is one click. Pre-existing interplay kept: a fresh tail take before an existing continuation stales that continuation exactly as a new version does today (STALE + Rechain UI).
- **Selection is not structure:** not freeze-gated; refused only while a video op is in flight or the file is missing; no-op when the effective clip doesn't change. Undo rides `ShotPictureStateSnapshot`.
- **Preview never mutates; USE is the only mutation.** Partial-render reuse base stays `activeRenderVersion` (a failed render's landed clips stay reusable) with selections overlaid last.
- **Why not generalize `ShotContinuationRecord` to pairs:** it would duplicate every version clip into a second mutable ledger and need a migration; deriving takes from the retained versions keeps one source of truth and zero migration. Recorded in THOUGHTS.
